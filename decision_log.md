# Decision log

Format: **Decision | Reason | Evidence (count)**. Counts come from `reports/cleaning_log.csv` (rules applied in order; each row counted under the first rule that removed it). Raw rows before rule 1: 1,067,371.

## DE2 — cleaning (`src/clean.py`, `notebooks/02_clean.ipynb`)

- Rule 0 — Normalise `StockCode` to str/strip/upper, `Invoice` to str/strip, `Description` to str; leave `Customer ID` as float until rule 7 | Raw columns mix Python `int` and `str` (932,385 int vs 134,986 str StockCodes; 1,047,871 int vs 19,500 str Invoices; 4 int Descriptions), so string ops and parquet writing need one type; lower-case `m` / `gift_0001_*` are the same codes as `M` / `GIFT_0001_*` | 0 rows removed
- Rule 1 — Drop `Year 2010-2011` rows with `InvoiceDate <= 2010-12-09 20:01:00` (max date of `Year 2009-2010`), then concatenate | DE1 showed the two sheets overlap for 9 days and every row in that window is an exact copy of a row in the earlier sheet | 22,523 rows removed (1,067,371 -> 1,044,848)
- Rule 2 — Drop exact duplicate rows (all columns equal), keep first | A line repeated inside the same invoice at the same timestamp/price is an export artefact, not two purchases | 11,812 rows removed (-> 1,033,036)
- Rule 3 — Drop cancellation invoices (`Invoice` starts with `C`) | Cancellations are negative-quantity reversals, not product interest | 19,104 rows removed, 8,292 distinct `C` invoices (-> 1,013,932)
- Cancellations removed but original purchases kept: a bought-then-returned item still signals product interest for recommendations. | Netting a return against its purchase would erase evidence that the customer chose that product; for a recommender the choice is the signal | 19,104 cancellation rows dropped, 0 original purchase rows touched
- Rule 4 — Drop `Quantity <= 0` | After rule 3 these are non-cancellation stock adjustments / damaged items with no customer purchase behind them | 3,393 rows removed (-> 1,010,539); 3,393 were not on a `C` invoice before rule 3 (DE1 counted 3,457 on raw data before overlap/duplicate removal); no `Quantity == 0` rows exist
- Rule 5 — Drop `Price <= 0` | Zero price is a free item or missing price, negative price is an accounting adjustment; neither is a real purchase | 2,626 rows removed (2,621 at price 0, 5 negative) (-> 1,007,913)
- Rule 6 — Drop non-product `StockCode`s: `POST, DOT, M, D, S, B, C2, BANK CHARGES, ADJUST, AMAZONFEE, CRUK, TEST001` and any code starting with `GIFT_`; keep `DCGS*` and `PADS` | Postage, carriage, manual lines, discounts, samples, bad-debt/bank/Amazon fees, commission, gift vouchers and test rows are not products a customer could be recommended; `DCGS*` and `PADS` have real product descriptions | 4,552 rows removed (-> 1,003,361); 38 non-standard codes reviewed, 18 dropped, 20 kept; `CRUK` had 0 rows left by this stage
- Rule 6 follow-up — `ADJUST2` (3 rows, "Adjustment by Peter on Jun 25 2010"), `TEST002` (1 row, "This is a test product.") and `SP1002` (2 rows, "KID'S CHALKBOARD/EASEL") are not on the exclusion list and are currently **kept** | Exclusion list was applied exactly as specified; these need an explicit decision | 6 rows affected in total
- Rule 7 — Drop rows with missing `Customer ID`, then cast `Customer ID` to int64 | A customer x product matrix needs a customer on every row; IDs are whole numbers stored as float only because of the NaNs | 226,761 rows removed (-> 776,600 final rows; 5,852 customers, 4,623 products, 36,598 invoices, 2009-12-01 to 2011-12-09)
